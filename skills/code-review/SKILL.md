# 代码审查 Skill

对代码进行全面审查，识别潜在问题并提供改进建议。

## 使用场景

- PR 提交前的自查
- 代码质量评审
- 新人代码指导

## 审查维度

### 1. 代码质量
- 命名规范（变量、函数、类）
- 函数长度和复杂度
- 代码重复
- 类型安全（TypeScript any 使用）

### 2. 安全性
- SQL 注入风险
- XSS 漏洞
- 敏感信息暴露
- 权限检查缺失

### 3. 性能
- 不必要的重渲染
- 内存泄漏风险
- N+1 查询问题
- 大对象深拷贝

### 4. 可维护性
- 单一职责原则
- 依赖方向正确
- 错误处理完善
- 日志和注释

## 执行流程

1. 读取目标文件或目录
2. 逐文件分析代码
3. 按维度分类问题
4. 输出结构化报告

## 输出格式

```markdown
## 代码审查报告

### 🔴 严重问题（必须修复）
- [文件:行号] 问题描述

### 🟡 建议改进（推荐修复）
- [文件:行号] 问题描述

### 🟢 优点
- 正面反馈
```

## 项目特定审查

### ESLint 集成
- 检查项目是否有 .eslintrc / eslint.config.js
- 如果有，运行 `npx eslint --format json` 获取现有 lint 结果
- 将 ESLint 发现作为审查基线，不再重复报告相同问题

### 自定义规则
- 检查 CLAUDE.md 中是否有团队特定的编码规范
- 将规范作为审查标准之一

## 审查深度增强

### 除了基础维度（命名、安全、性能），增加：
- **依赖分析**：新增 import 是否引入了不必要的依赖
- **类型安全**：any 类型使用、类型断言滥用
- **错误处理**：未捕获的 Promise rejection、空的 catch 块
- **测试覆盖**：修改的函数是否有对应测试
